## The gap this closes, and why it matters

Phase 8 already proves your bandit beats a naive baseline on a *fresh*
batch of synthetic data, generated for the purpose of the test. But that
raises a real, uncomfortable question a sharp judge might ask: **"How do
you know this bandit is safe to deploy against real, already-logged
production data, before you've run it live?"**

This is not a hypothetical concern — it's exactly the problem real
companies (Netflix, Spotify, Stripe) solve with **off-policy evaluation
(OPE)**: estimating how a *new* policy would have performed on *historical*
data that was actually generated by a *different* (old) policy, without
ever deploying the new policy live. This matters enormously in production
because you cannot ethically or safely A/B test a brand-new payment-retry
policy against real customers without some prior evidence it won't perform
worse than what's currently running.

## The core technique: Inverse Propensity Scoring (IPS)

The key insight: your baseline policy's logged decisions already tell you
*what arm was chosen* and *what happened* for a historical batch. A new
policy (your bandit) can be evaluated against this same historical log by
re-weighting each historical outcome by how likely the *new* policy would
have been to make the *same* choice the *old* policy actually made.

```
IPS estimate of new policy's value =
    (1/N) * sum over historical records of:
        [ new_policy_probability(chosen_arm | context) / old_policy_probability(chosen_arm | context) ]
        * observed_reward
```

If the new policy would have made the same choice the old policy actually
made, the ratio is close to 1 and that observation counts normally. If the
new policy would rarely have made that choice, the ratio shrinks the
observation's influence — this is what lets you estimate a *new* policy's
performance from *old* data, without ever running the new policy for real.

## Implementation

### `eval/off_policy_evaluation.py`

```python
import numpy as np
from dataclasses import dataclass


@dataclass(frozen=True)
class OPEResult:
    estimated_value: float
    effective_sample_size: float  # low ESS = low-confidence estimate, report this honestly
    n_records: int


def baseline_policy_probability(context_bucket: str, arm: str) -> float:
    """BaselinePolicy always chooses retry_immediate deterministically —
    probability 1.0 for that arm, 0.0 for all others. A real production
    system's logging policy would typically log actual probabilities if it
    were itself a randomized policy; document this simplification
    explicitly since BaselinePolicy is deterministic, which is a genuine
    edge case for IPS (see 'Limitations' below)."""
    return 1.0 if arm == "retry_immediate" else 0.0


def new_policy_probability(bandit, context_bucket: str, arm: str, n_samples: int = 200) -> float:
    """Thompson Sampling doesn't have a closed-form probability for 'arm
    X gets chosen' — estimate it via Monte Carlo: repeatedly sample from
    each arm's current Beta distribution and count how often `arm` wins."""
    stats = bandit.get_stats(context_bucket)
    wins = 0
    for _ in range(n_samples):
        sampled = {a: np.random.beta(alpha, beta) for a, (alpha, beta) in stats.items()}
        if max(sampled, key=sampled.get) == arm:
            wins += 1
    return wins / n_samples


def evaluate_off_policy(historical_log: list[dict], bandit) -> OPEResult:
    """historical_log: list of {context_bucket, chosen_arm, reward} from a
    PAST baseline run (Phase 8's batch_run_metrics / audit_log for a
    policy='baseline' run)."""
    weights = []
    weighted_rewards = []
    for record in historical_log:
        p_new = new_policy_probability(bandit, record["context_bucket"], record["chosen_arm"])
        p_old = baseline_policy_probability(record["context_bucket"], record["chosen_arm"])
        if p_old == 0:
            continue  # the old policy could never have produced this record with p=0 — skip, avoid divide-by-zero
        weight = p_new / p_old
        weights.append(weight)
        weighted_rewards.append(weight * record["reward"])

    estimated_value = float(np.mean(weighted_rewards)) if weighted_rewards else 0.0
    # Effective sample size — a standard IPS diagnostic. Low ESS relative to
    # n_records means a small number of records are dominating the
    # estimate, and the result should be reported with explicit caution.
    ess = (sum(weights) ** 2) / sum(w ** 2 for w in weights) if weights else 0.0

    return OPEResult(estimated_value=estimated_value, effective_sample_size=ess, n_records=len(historical_log))
```

### Wiring this into your workflow

```python
# Before "deploying" your bandit (i.e., before presenting it as your final
# demo policy), run this against a batch that was ALREADY generated by the
# baseline policy in Phase 8:
baseline_log = load_audit_log_for_run(db_session, baseline_run_id)
ope_result = evaluate_off_policy(baseline_log, bandit)

print(f"Estimated bandit performance on baseline-logged data: {ope_result.estimated_value:.3f}")
print(f"Effective sample size: {ope_result.effective_sample_size:.1f} / {ope_result.n_records}")
```

## Limitations to state honestly (this is itself a signal of maturity)

- **Low effective sample size is a real risk here** specifically because
  `BaselinePolicy` is deterministic (always `retry_immediate`) — IPS
  fundamentally struggles when the logging policy has near-zero
  probability of ever choosing the arms your new policy actually wants to
  try. State this limitation explicitly rather than hiding it: *"IPS gives
  us a directional sanity check against baseline-logged data, but our
  primary evidence remains the controlled online experiment in Phase 8,
  precisely because our baseline's determinism limits how much OPE alone
  can tell us."* This honest caveat is more impressive to a technical judge
  than an overstated claim would be.
- This technique is a **secondary, corroborating piece of evidence**, not
  a replacement for Phase 8's direct online comparison — present it that way.

def test_ope_returns_low_ess_when_policies_diverge_heavily():
    """A logging policy that never chooses the arms the new policy wants
    should produce a low effective sample size — this test proves the
    diagnostic actually detects the exact limitation described above,
    rather than silently producing a falsely confident number."""
